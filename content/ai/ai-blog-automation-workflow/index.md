> 반복 작업을 자동화하면 창작 에너지를 아이디어에 집중할 수 있다.

---

## 왜 자동화를 만들었는가?

개발자로서 AI는 이제 단순히 코드를 작성하는 도구를 넘어 협업을 위한 동료처럼 사용해야 한다 생각한다. AI와 함께 진행하는 **Workflow**를 만들고 운영하는 과정을 학습하고자 블로그 자동화 과정을 구상했다.

블로그 작성은 이 학습에 적합한 대상이다. 파일 생성, 검토, 배포로 이어지는 흐름이 반복되고, 각 단계의 규칙이 명확해 AI 위임 결과를 검증하기 쉽다.  
특히 어떤 작업을 AI에게 위임할 수 있는지, 지시사항을 어떻게 구조화해야 일관된 결과가 나오는지, 사람과 AI의 역할을 어떻게 나눠야 하는지를 실제 블로그 운영을 통해 체득하고자 했다. 

---

## 전체 워크플로우

작성부터 배포까지 세 개의 커맨드로 구성된다.

| 커맨드 | 역할 |
| :--- | :--- |
| `/new-post <섹션> <주제>` | 초안 작성 → 자동 검토 → 자동 수정 |
| `/review` | 기존 파일 수동 검토 |
| `/deploy "메시지"` | diff 분석 후 배포 |

사용자의 개입은 처음(주제 입력)과 끝(초안 기반하여 수정. 최종 배포) 두 지점에만 있다.  
나머지는 AI가 순서대로 처리한다.

---

## 핵심 구성 요소

### Skills 시스템

Claude Code의 **Skills**는 `.claude/commands/` 디렉터리에 마크다운 파일로 정의하는 커스텀 커맨드다. 파일마다 AI에게 전달할 지시사항 전체를 담는다.

이 블로그에는 현재 세 개의 스킬을 사용한다.

```text
.claude/commands/
├── new-post.md      # 초안 작성 파이프라인 전체
├── review.md        # 글 검토 기준 적용
└── deploy.md        # 배포 + diff 학습
```

각 스킬은 독립적으로 작동한다. `new-post.md`는 파일 생성부터 원본 사본 저장까지 초안 작성 파이프라인 전체를 정의하고, 글 작성 중 `review.md`를 활용해 검토한다. 마지막으로 `deploy.md`는 배포 전 diff를 분석해 사용자 편집 패턴을 학습한다. 스킬을 수정해도 다른 스킬에 영향을 주지 않는다.

### 참조 파일 구조

글쓰기에 관여하는 파일은 아래와 같다.

| 파일 | 역할 | 갱신 방식 |
| :--- | :--- | :--- |
| `write-style-guide.md` | **구조** — 섹션 흐름, 문체, 작성 방법 | 수동 |
| `writing-voice.md` | **내용** — 추가·제거 패턴, 관점, 분위기 | `/deploy` 마다 갱신 |

검토 기준(사실 오류, 중복, 주제 이탈, 내용 충돌 등)은 `review.md` 스킬에 직접 내장되어 있다.

## 블로그 작성 파이프라인 소개

블로그를 작성하는 단계를 순서대로 보면 다음과 같다.

### 1. `/new-post` Skill로 초안 작성

{{< flowchart >}}파일 생성 | 웹 검색 | 초안 작성 | 검토 및 수정 | 사본 생성 {{< /flowchart >}}

**파일 생성**  
섹션과 주제를 파싱해 슬러그를 결정하고 Hugo로 파일을 생성한다.

```text
hugo new content/<섹션>/<slug>/index.md (페이지 번들)
```

**웹 검색**  
주제 관련 쿼리로 최신 정보를 수집한다.

**초안 작성**  
`write-style-guide.md` 구조 규칙과 `writing-voice.md` 내용 패턴을 함께 참조하여 본문을 작성한다. 구조는 스타일 가이드가, 무엇을 담을지는 누적된 패턴이 이끈다.

**검토 및 수정**  
`review.md` 스킬에 내장된 기준(사실 오류, 웹 검색 확인, 중복, 주제 이탈, 내용 충돌)으로 초안을 검토하고 경고·위반 항목을 즉시 수정한다. 수정 내역은 요약 형식으로 출력된다.

**사본 생성**  
최종 초안을 `.orig.md`로 저장하고 완료를 보고한다.

---

### 2. 초안 수정

사용자가 직접 작성된 초안을 수정한다.

이때 `/review` 스킬을 활용하여 내용상 중복되는 부분이 없는지, 문맥이 충돌하거나 정보에 오류가 있는 등 발생할 수 있는 문제 상황에 대처한다.

---

### 3. `/deploy`를 통한 배포

수정된 초안(`index.md`)과 AI 원본 사본(`.orig.md`)을 비교하여 사용자의 편집 패턴을 `writing-voice.md`에 누적한다.

```shell
#서브 모듈(테마) 업데이트
git submodule update --remote

# 커밋 메시지 작성
msg="rebuild: $(date +"%Y-%m-%dT %H:%M:%S%z")"

# 원본 사본 삭제
find content -name "*.orig.md" -delete

# main에 push 및 Action이 자동 빌드 & gh-paghes 배포
git add .
git commit -m "$msg"
git push origin main
```

`deploy.sh` 로 따로 분리한 건 매번 모든 수정 사항마다 학습할 필요는 없으므로, 간단한 수정 등은 스크립트만 실행해 진행한다.

## 자동화가 대체하지 못하는 것

AI가 처리하는 것은 **형식**과 **규칙**이다. 내용의 밀도는 여전히 사람에게 달려 있다.

- **주제 선정**: 무엇을 쓸지는 AI가 결정하지 않는다
- **경험 서술**: 직접 겪은 맥락과 실패는 생성할 수 없다
- **최종 사실 확인**: 웹 검색을 거쳐도 오류 가능성은 남는다

이 시스템의 목표는 글을 대신 쓰는 것이 아니라 **글 쓰는 데 드는 부담을 줄이는 것**이다. 백지 공포증이라는 말처럼 처음부터 글을 쓰는 건 부담스러운 일이지만 시스템의 도움으로 간편하게 글을 쓰게 되고 습관을 만들어 갈 수 있다.
